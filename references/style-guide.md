## 1. 设计目标
- 面向客户的方案附件：**像实际拓扑，不像示意图**——每台物理设备单独出现、每条物理链路单独画线（并行链路画成 N 条平行线 + 聚合椭圆）。
- 信息分三层：图形（设备/连线）→ 图上就近标注（链路规格、角色）→ 底部面板（图例、清单/变更表、说明）。
- 视觉克制：白底、浅色分区、少量强调色；颜色语义固定，跨图一致。

## 2. 画布与网格
- 默认画布 `2420 × 1580`（横向 A3 比例，导出 PNG 后插入 Word/PPT 清晰）。内容多时加高，不要缩小字号。
- 左边距 40（分层标签），分区从 x=150 开始，右边界 x=2370。
- 网格 10px；所有坐标取 10 的倍数或设备中心对齐，便于 draw.io 二次编辑。
- 字体统一 `Microsoft YaHei`。

## 3. 页面结构（自上而下）
| y 区间 | 内容 |
|---|---|
| 22–66 | 主标题，30px 粗体居中，色 `#1B2631` |
| 68–72 | 640px 宽蓝色下划线 `#2E6DA4` |
| 74–100 | 副标题 13px `#5D6D7E`，一句话概括涉及机房 / 关键关系 |
| 110–1120 | 分区主体（分层标签同高度带） |
| 1160–1540 | 底部三栏：图例 / 表格 / 说明，高 380 |

标准四行分层（中心 y）：核心/汇聚 270、安全防护 480、服务器交换 690、计算资源 950。对应分层标签区间：
`(180,350) (400,550) (610,760) (870,1110)`。增减层时保持行距约 210。

## 4. 分区（楼宇 / 机房）
- 外框：直角矩形，2px 描边 = 标题栏色，浅色填充。
- 标题栏：高 40，实色填充，白字 18px 粗体 + 13px 副说明（角色/阶段）。
- 配色语义（`ZONE`）：
  - `green` `#2E8B57 / #F2FAF4`：旧机房 / 现网 / 被改造方
  - `blue` `#2E6DA4 / #F2F7FC`：新机房 / 目标 / 新建方
  - `gray` `#7F8C8D / #F7F8F8`：闲置 / 待拆除 / 仅迁出
  - `orange` `#CA6F1E / #FDF6EE`：外网 / DMZ
  - `purple` `#7D3C98 / #F7F2FA`：灾备 / 云
- **左旧右新**：搬迁/改造类图，旧机房放左、新机房放右；搬迁前、后两张图分区位置保持一致，方便对照。
- 分区间留 80px 间隙，跨区链路的标注居中放在间隙上（白底文字可压住分区边线）。
- 次要机房（只有闲置设备等）可上下叠放在右侧，宽 760。

## 5. 左侧分层标签
- x=40，宽 80，圆角，`#EBF0F5` 填充 / `#AEB6BF` 描边，14px 粗体 `#34495E`。
- 文字逐字竖排（每字 `<br>`），不要用旋转文字。

## 6. 设备图标
使用 draw.io 内置 **Cisco 经典** stencil（已验证可渲染），白色描边 2px，填充色表达角色：

| kind | 尺寸 | stencil | 用途 | 默认色 |
|---|---|---|---|---|
| l3 | 64×64 | cisco.switches.layer_3_switch | 核心 / 汇聚 / 多业务网关 | core `#0B3D91` 或 agg `#117A65` |
| sw | 100×40 | cisco.switches.workgroup_switch | 数据中心 / 服务器交换机 | `#2471A3` |
| sw_s | 90×34 | 同上 | 接入交换机 | `#5B7DB1` |
| fw | 64×48 | cisco.security.firewall | 防火墙 | `#C0392B` |
| srv | 46×66 | cisco.servers.fileserver | 服务器 / ESXi | `#1F618D`，闲置 `#A6ACAF` |
| router | 64×44 | cisco.routers.router | 路由器 | `#1A5276` |
| pc | 50×46 | cisco.computers_and_peripherals.pc | 终端 | `#566573` |

颜色语义：**深蓝 = 全网核心；墨绿 = 汇聚 / 原核心降级；红 = 安全设备；灰 = 闲置/下架**。同型号不同角色（如同为 DPX8000 的"新增核心"与"原有楼宇汇聚"）必须靠颜色 + 组标签 + 徽标三重区分。

设备标签：`<b>型号 #序号</b><br>11px 灰色角色`。
- 默认标签在下方；**若有竖向连线从图标下方/上方穿过，标签改到左右两侧**（成对设备：#1 在左、#2 在右）。
- 新增图标类型时用官方 MCP `search_shapes`（如 `cisco wireless access point`）取得官方 style 与尺寸，只取其中的 `shape=...` 加入 `ICON`，配色仍按本指南（白描边 + 角色色）。优先选 `mxgraph.cisco.*` 经典系列，保持图标风格统一。

## 7. 设备组框、胶囊标签、状态徽标
- **设备组框**：虚线圆角（`dashPattern=6 4`，1.5px），白色填充，描边色 = 组内设备主色。用于：堆叠/CSS/IRF/虚拟化、主备、集群、同类接入组。
- **胶囊标签**：组框左上（压在上边框上，y-11），高 22，实色白字 11px 粗体，内容格式 `关系 · 角色`，如 `CSS 集群 · 门诊楼汇聚（原核心降级）`、`主备 · 服务器区防火墙`、`虚拟化 · 服务器交换`。
- **状态徽标**：组框右上同一水平线：`新增` 橙 `#E67E22`、`原有` 灰 `#7F8C8D`、`迁入` 紫 `#8E44AD`、`下架` 深灰、`规划` 蓝。只有资料明确说明的状态才标。
- **框上方有大量连线进入时（如服务器集群框），胶囊和徽标移到下边框**（`bottom=True`），避免连线压字。
- 成对设备之间画 5px 深色粗线表示虚拟化/堆叠互联（主备防火墙改用绿色虚线 HA）。

## 8. 连线体系
全部 **直线**、无箭头、`rounded=0`，锚点用 `exitX/entryX + Perimeter=0` 精确落在边框上（`Doc.e` 已封装），保证在 draw.io 中拖动设备时线跟随。

| 键 | 样式 | 语义 |
|---|---|---|
| 10g | 橙 `#E67E22` 2px | 万兆 |
| 1g | 蓝 `#2E86C1` 2px | 千兆 |
| x10g | 深橙 `#D35400` 3px | 跨楼 / 骨干万兆（强调） |
| gen | 灰 `#566573` 2px | 规格未提供的互联（不写速率） |
| ha | 绿 `#27AE60` 虚线 | 主备心跳 |
| virt | 近黑 `#1B2631` 5px | CSS / IRF / 堆叠 / 虚拟化互联 |
| vm | 紫 `#8E44AD` 虚线 2.5px | 虚拟化集群等逻辑关系 |
| wan | 青 `#16A085` 长虚线 | 运营商 / 专线 |
| mgmt | 浅灰点线 | 管理 / 带外 |

规则：
- **并行链路**：N 条平行线，间距 10（水平）或 20（竖直），两端（或上端）加黑色描边空心椭圆表示聚合（`parallel_h` / `parallel_v`）。
- **双归属**：每台服务器顶边两点（中心 ±9）分别连两台交换机底边，入点在交换机底边按服务器序号均匀分布（`dual_home`）——形成规整的交叉扇形。
- **单归属多链路**：入点按顺序分布，线互不交叉（`fan_in`）。
- **连到设备组还是成员**：资料只说"A 上联 B（B 为虚拟化组）"而未给逐端口接线时，连到**组框边线**，不要指定到某台成员。
- **折线**：仅在需要绕开时用一个直角折点；多条折线时，远端目标的水平段放在更靠上的 y，避免与近端竖线交叉。
- 不同层之间优先竖直线；同层跨区用水平线。

## 9. 标注文字
- 链路规格标注：放在线旁空白处，12px 粗体，颜色与线同色，如 `2×10GE 多模 · 链路聚合`；第二行常规字说明接法。
- 跨区主链路标注：14px 粗体深橙，白底，置于线上方；下方 11px 灰字白底写 `跨楼互联：A ⇄ B`。
- 逻辑关系标注（集群）：白底 + 同色圆角边框的标签框，两行（粗体名称 + 组成）。
- 范围外下游：11px 灰字 `▼ 下联 xxx（本图略）`。
- 不画进本图但必须交代的内容（存储/FC 另见独立图、现状说明）：灰色虚线圆角说明框 11px（`note_box`）。

## 10. 底部三栏
y=1160，高 380，x 从 150 到 2370，间距 30：
1. **图例**（宽 700）：左列设备图标（缩小版）+ 组框 + 状态徽标，右列线型 + 聚合椭圆。只列图中实际出现的元素。
2. **表格**（宽 800）：现状图用"设备清单（位置/设备/数量/角色）"；改造/搬迁图用"设备变更说明（类别/设备/数量/位置说明）"，类别着色：新增橙、迁移紫、下架灰。数量不确定时填"—"。
3. **说明**（余宽）：编号条目 4–6 条，复述关键关系、链路规格、阶段计划，最后一条写"具体端口编号、逐端口接线以实施阶段确认为准"。

## 11. 布局套路

### 11.1 单机房分层（现状图）
核心组居中于分区上部 → 防火墙 → 服务器交换机 → 服务器横排（间距 160）+ 集群框。链路规格标注放竖线右侧，接入说明放左侧空白。

### 11.2 双机房对称（搬迁后 / 双活）
```
| 左区(旧, 宽860)          | 80 | 右区(新, 宽1280)                          |
| 汇聚组 cx=580            |====| 核心组 cx=1440        原有汇聚组 cx=2110  |
| FW 主备 cx=580           |    | FW 主备 cx=1440                           |
| 服务器交换 cx=580        |    | 服务器交换 cx=1440 ── 接入交换组(右下)    |
| 服务器×3 + 集群框        |----| 服务器×4 + 集群框                         |
```
- 两侧核心/汇聚组位置要使跨区并行线的中点落在 80px 间隙中心（计算 `mid=(x1+x2)/2`）。
- 两区"服务器区标准块"结构相同（`server_block` 见示例），视觉上形成对照。
- 跨机房集群线用 `vm` 虚线连两个集群框，标签框居中在间隙。

### 11.3 现状 + 闲置机房
主机房宽 1380 放左；右侧上下叠放两个宽 760 的小分区（汇聚机房、闲置机房）。闲置设备用灰色图标 + 灰色组框，不连线，并用一行灰字说明现状。

## 12. 防碰撞与美观检查清单
生成后**必须运行 `scripts/topo_check.py`**：前 3 项与留白/越界由 lint 自动报告（ERROR/WARN），其余看 `--png` 输出的布局预览（问题处洋红框，可 `--crop` 放大）。预览为近似渲染（图标为色块），最终观感以 MCP 打开的 draw.io 编辑器为准：
- [ ] 无文字被连线穿过（尤其设备下方标签、组框胶囊）。
- [ ] 无文字互相重叠；标注不压在图标上。
- [ ] 跨区标注居中于间隙，白底干净。
- [ ] 分区内留白均衡，没有一侧大片空白（必要时整体平移该区内容的 cx）。
- [ ] 同一层设备中心 y 一致；成对设备间距 160。
- [ ] 图例只含图中出现的元素；表格/说明与图一致。
- [ ] 底部面板没有大面积空白（内容少就降低面板高度并同步页高）。

## 13. 准确性原则（不编造）
- 端口号、逐端口接线、链路速率/介质、数量、厂商、"新增/原有"状态：**资料没给就不画、不写**。规格未知用 `gen` 灰线；数量未知填"—"。
- 资料给出的数字（如"4 条万兆聚合"）必须在图形（4 条线）、标注、说明三处一致。
- 被明确排除的内容（如存储/FC 另有图）只用说明框交代，不画设备与连线。
- 交付时向用户列出所有"按不编造处理"的点，请其确认。

## 14. 官方 draw.io MCP 使用约定
两种官方服务器：
- 本地 stdio `npx -y @drawio/mcp`（推荐）：`open_drawio_xml`、`open_drawio_csv`、`open_drawio_mermaid`、`search_shapes`、`list_pages`、`get_page`、`set_page`、`get_drawio_reference`。图数据只在 URL 片段里传递，不离开本机；支持 `DRAWIO_BASE_URL` 指向自建 draw.io。
- 托管 HTTP `https://mcp.draw.io/mcp`：`create_diagram`、`search_shapes`、`get_drawio_reference`。支持 MCP Apps 的客户端会在对话内显示图，其他客户端返回链接。

约定：
- **只用默认参数打开**（可加 `lightbox` 只读展示）。不传 `postLayout`/`routing`/`direction`：ELK 会重排设备，libavoid 会把直线改成正交折线，都会破坏本风格。
- MCP 会对 XML 做修复/规范化：实测只给连线补 `labelBackgroundColor=default` 类样式、数字格式化，几何坐标 0 变化。若未来版本改变行为，以本地 `.drawio` 文件为准。
- `content` / `xml` 参数传整个 `.drawio` 文件文本。超大图（URL 过长）时改为只交付本地文件，让用户用 draw.io 打开。
- 用户手工改过的文件：`get_page` 读取 → 局部修改 → `set_page` 回写 → `topo_check.py` 复查。不要用生成脚本覆盖用户的手工调整，除非用户同意。
- 环境未挂载 MCP 工具时，用 `scripts/drawio_mcp.py` 调用同一套工具（自动设置 `DRAWIO_BROWSER=off`，只返回链接；`--browser` 自动打开）。
